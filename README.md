# RAW Studio — Python RAW Processor

Настолно приложение на български за автоматична обработка на RAW снимки и
експорт в JPG или PNG. Интерфейсът е с CustomTkinter, а декодирането е с
rawpy/LibRaw. Работи локално; снимките не се изпращат към услуга.

![Тъмна тема с генериран тестов DNG](docs/interface-dark.png)

В `docs/` има снимки на действителния интерфейс в тъмна и светла тема.

## Бързо стартиране в Windows

1. Инсталирай **Python 3.12, 64 бита** от <https://www.python.org/downloads/>.
   При инсталацията включи Python Launcher и „Add Python to PATH“.
2. Разархивирай проекта в папка.
3. Стартирай **`start_windows.bat`** с двойно щракване.
   При първото пускане той създава `.venv` и инсталира зависимостите.
   Следващите пускания използват вече инсталираните пакети.

Алтернативно, от терминал в папката на проекта:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe raw_processor.py
```

Не е необходимо да активираш виртуалната среда или да променяш PowerShell
Execution Policy.

## Linux и macOS

Използвай Python 3.11 или по-нов; препоръчителният и проверен тук е Python 3.12.
Необходима е графична сесия и работещ `tkinter`.

За Debian/Ubuntu, ако липсват Tk или модулът за виртуални среди:

```bash
sudo apt install python3-tk python3-venv
```

Стартиране:

```bash
sh start_unix.sh
```

Или ръчно:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python raw_processor.py
```

За macOS инсталаторът от python.org включва Tkinter; при други Python
дистрибуции може да е необходим отделен Tk пакет.

## Един самостоятелен Python скрипт

**`RAW_Studio.py`** съдържа целия код на приложението в един файл: `RawEngine`,
пакетната обработка и `AppGUI`. Нужни са същите зависимости, но другите Python
файлове от проекта не са необходими за неговото стартиране:

```bash
python -m pip install -r requirements.txt
python RAW_Studio.py
```

Този файл се генерира от модулния код чрез `python tools/build_standalone.py`.
При промени редактирай модулите и генерирай файла отново.

## Как се използва

1. Натисни **„Добави RAW файлове“** за една или няколко снимки, или избери папка.
   „Включи подпапките“ се отнася за следващото избиране на папка.
   Няколко избора се добавят към един списък; дублиращите се файлове се премахват.
2. Избери снимка от менюто над прегледа.
3. Настрой баланса на бялото, светлината, контраста и детайла.
   Прегледът се обновява автоматично след кратка пауза при промяна на настройките.
4. Избери **JPG** или **PNG** и папка за резултатите. Първоначално се предлага
   подпапка `processed` до първата избрана снимка.
5. Натисни **„Обработи всички снимки“**. За единичен експорт избери само един RAW.
6. Следи броя завършени снимки, грешките и дневника. „Отвори резултатите“ отваря
   изходната папка в файловия мениджър.

По време на обработката настройките са заключени. Всички снимки в една серия
получават настройките, избрани при старта.

## Настройки и качество

| Настройка | Поведение |
| --- | --- |
| От камерата | Балансът на бялото от RAW метаданните; автоматичен баланс при липсващи валидни коефициенти. |
| Автоматичен (LibRaw) | Баланс на бялото, изчислен от декодера. |
| Gray World | Допълнително балансира средните стойности на каналите след камерата. |
| Shades of Gray | Вариант със степен 6, който дава по-голяма тежест на светлите пиксели. |
| Автоматична експозиция | Консервативна корекция по 98-ия персентил на линейната яркост, ограничена до ±2 EV. |
| Експозиция | Допълнителна ръчна корекция от −3 до +3 EV. |
| Локален контраст | CLAHE върху 16-битовия L канал в Lab, смесено с първоначалния канал според избраната сила. |
| Премахване на шум | `fastNlMeansDenoisingColored`; по-високата сила може да изглади фините детайли. |
| Изостряне | Изостряне на яркостта с unsharp mask. |
| JPG качество | 1–100%; JPG винаги е 8-битов и използва компресия със загуба. |
| PNG компресия | 0–9; променя размера на файла и времето за запазване, **не качеството**. |
| PNG дълбочина | 8 или 16 бита на канал; по подразбиране 16 бита. |

Декодирането е **16-битово линейно RGB**, а корекциите използват `float32`.
След експозицията се прилага sRGB тонална крива. За CLAHE L каналът се преобразува
в `uint16`, докато a/b каналите остават с плаваща запетая.

Цветният OpenCV NLM филтър изисква 8-битово входно изображение. Приложението
прехвърля обратно в изображението с висока точност разликата, получена от
филтъра, вместо да замени целия сигнал с 8-битов. Това не е изцяло 16-битов NLM
алгоритъм, но избягва свеждането на целия PNG16 резултат до 256 нива на канал.

Препоръчителна начална настройка: баланс от камерата, автоматична експозиция,
CLAHE 30%, изостряне 0.45 и изключен NLM. Прецени резултата на собствените снимки;
автоматиката не може да разпознае всяко художествено намерение.

## Преглед и безопасно запазване

- **Преди** показва декодираното изображение със същия избран баланс от
  камерата/LibRaw, преди допълнителните автоматични корекции. Това е визуализиран
  RAW, а не необработени сензорни данни.
- Бързият преглед използва `half_size=True` и допълнително умаляване. Неговите
  размери в информационния ред са размерите на прегледа.
- **Точен преглед** обработва пълната резолюция, след което умалява само
  изображението за показване. Дори тогава интерфейсът го побира в прозореца.
- Експортът **винаги** декодира и обработва отново RAW в пълната резолюция;
  никога не записва умаления преглед.
- По подразбиране съществуващите резултати се запазват. Новите получават
  суфикс `_001`, `_002` и т.н. Еднакви имена от различни папки/RAW формати се
  разграничават по същия начин. Експортът е в една обща изходна папка.
- Презаписването се включва само с отделния превключвател. RAW оригиналите
  никога не се използват като изходни файлове.
- Резултатът първо се записва във временен файл, а след успешно кодиране се
  публикува чрез атомарна замяна. Неуспешен нов експорт не оставя частичен JPG/PNG.
- Повредена или неподдържана снимка се записва като грешка в дневника, след
  което обработката продължава със следващата.
- **Спри** работи между безопасни етапи. Изпълняваща се LibRaw/OpenCV операция
  трябва да приключи, преди заявката да бъде изпълнена. Вече запазените снимки
  остават на място. Затварянето на приложението използва същото поведение.

## Архитектура

| Файл | Роля |
| --- | --- |
| `raw_processor.py` | Стартиране на модулното приложение и тъмната тема. |
| `raw_engine.py` | `RawEngine`, `ProcessingParams`, RAW декодиране, корекции, преглед и експорт. |
| `batch.py` | Търсене на RAW файлове, уникални изходни имена и пакетна обработка. |
| `app_gui.py` | `AppGUI`, две колони, контроли, преглед, прогрес и дневник. |
| `RAW_Studio.py` | Генерирана самостоятелна версия на целия код. |
| `tests/` | Проверки на декодирането, цветовете, точността, файловете и отзивчивостта на GUI. |

Нишката за обработка изпраща събития към `queue.Queue`. Главната GUI нишка ги
прочита с `after()` и обновява интерфейса. Нито работниците, нито RAW двигателят
четат Tk променливи или обновяват widgets. Обработва се по една снимка, за да
се ограничи използваната памет.

RAW двигателят може да се използва и без интерфейса:

```python
from raw_engine import ProcessingParams, RawEngine

engine = RawEngine()
params = ProcessingParams(
    white_balance="camera",
    denoise=False,
    output_format="png",
    png_bit_depth=16,
)
result = engine.process_file("photo.CR2", "processed/photo.png", params)
print(result.output_path, result.dimensions)
```

## Проверки и GitHub

Тестовете генерират малък Bayer DNG и го декодират с действителния LibRaw,
вместо да подменят RAW декодера с mock. За тестовете се изисква Python 3.12+.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

На Linux с виртуален дисплей:

```bash
xvfb-run -a python -m pytest -q
```

Без графичен дисплей GUI тестовете се пропускат; тестовете на двигателя и
пакетната обработка работят без прозорец.

На Windows стартирай GUI проверките с `python tools/check_gui.py`. На Linux
използвай `xvfb-run -a python tools/check_gui.py`. Скриптът изпълнява всеки тест
в отделен процес, за да не се пренася Tk състояние между тестовете.

В `.github/workflows/tests.yml` има готов workflow за Python 3.12 на
Windows, Linux и macOS, с GUI проверки на Linux и Windows. Той ще се изпълнява, след
като качиш проекта в избрано GitHub хранилище. Самият workflow не е изпълняван
в GitHub като част от подготовката на този пакет.

Локалната проверка е на Linux с Python 3.12. Истински CR2/NEF/ARW файлове от
твоя фотоапарат не са предоставени, затова съвместимостта с конкретния модел
трябва да се провери с твоя снимка.

## Ограничения и чести проблеми

- RAW разширението служи за намиране на файловете. Поддръжката на конкретен
  фотоапарат, компресия и RAW вариант зависи от включения LibRaw. Неподдържан
  файл се отчита като грешка, без да прекъсва цялата серия.
- Изходните файлове са sRGB RGB изображения. EXIF, GPS, XMP и ICC метаданните
  не се копират. Ориентацията от RAW се прилага при декодирането.
- Не се прилагат обективни профили, корекция на перспективата или специални
  цветови профили като в Lightroom/Camera Raw.
- Големите RAW файлове използват значителна RAM; NLM може да бъде бавен при
  пълна резолюция. Изключи го, ако искаш по-бърза обработка.
- `No module named ...`: инсталирай зависимостите със същия Python, с който
  стартираш приложението.
- `No module named tkinter`: инсталирай Tk за използваната Python дистрибуция.
- `no display name ...`: приложението е настолно и изисква графична сесия.
- Ако инсталирането на пакети поиска компилатор, провери дали използваш
  64-битов Python 3.12 и дали `pip` е актуален.
- Използван е `opencv-python-headless`, защото прозорците са на Tkinter;
  функционалностите за обработка на изображения в OpenCV са налични.
